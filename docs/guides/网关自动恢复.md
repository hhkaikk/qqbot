# QQ自动恢复维护

自动恢复服务独立运行在部署 QQ 网关的 Linux 服务器。应绑定你自己的机器人账号，本地电脑不需要持续开机；源码不会携带任何账号登录态。

密码回退是可选能力。`install-gateway-guard.sh` 不保存密码，仓库里的 service 默认也不加载凭据。需要密码回退时，由管理员单独准备匹配机器人账号的 systemd 加密凭据，并通过 service override 设置 `LoadCredentialEncrypted=qq-login:/etc/qqbot/credentials/qq-login.cred`。没有这项配置时，只执行可用的无密码恢复及状态检查，不能把安装成功当作密码回退已就绪。

正常在线时只做回环HTTP检查，不请求模型、不消费DS Token、不执行QQ登录。离线后先等3分钟，快速登录失败且明确身份过期时才回退密码。网络异常按3、5、15分钟退避；每小时快速登录最多3次、密码最多2次，预算用尽等待窗口释放。出现密码错误、验证码、设备确认或不确定的登录拒绝时停止重试。

控制台QQ状态会显示“恢复中”“需要处理”或“接口异常”。“需要处理”时打开原有QQ登录页面按提示操作，不能通过反复重启清除验证。确认实际新号在线后，守护器自行清除人工阻断；若管理员已修正配置但仍离线，可在服务器运行一次受控解除：

```sh
systemctl stop qqbot-gateway-guard.timer
systemctl stop qqbot-gateway-guard.service
systemd-run --wait --pipe --collect --unit=qqbot-gateway-manual-check \
  -p LoadCredentialEncrypted=qq-login:/etc/qqbot/credentials/qq-login.cred \
  /usr/bin/python3 -I /usr/local/libexec/qqbot-gateway-guard.py --reset-block
systemctl start qqbot-gateway-guard.timer
```

只在已排除原先验证码/密码错误原因后使用该操作；它会重新允许一次恢复流程，小时预算仍保留。

管理员查看状态：

```sh
systemctl status qqbot-gateway-guard.timer
journalctl -u qqbot-gateway-guard.service --since '1 hour ago' --no-pager
cat /run/qqbot-gateway-guard/status.json
```

密文在 `/etc/qqbot/credentials/qq-login.cred`，由系统宿主密钥保护，不能单独复制到别的机器解密。不要输出解密内容、把密码放进命令参数，或将凭据放到项目/GitHub。换QQ时需单独更新账号配置和绑定凭据；不匹配时服务会停止。

程序位于root保护的 `/usr/local/libexec/qqbot-gateway-guard.py`，原生诊断模块及启动包装位于 `/usr/local/share/qqbot-gateway-runtime/`。项目源码修改不会自动影响root运行副本；审核后运行部署脚本安装。升级NapCat前必须重新验证补丁唯一锚点及启动解压过程，不能直接换成latest。

撤回本轮自动恢复时，先执行 `systemctl disable --now qqbot-gateway-guard.timer`，再停止同名service。此操作不影响正在运行的QQ、桥接或DSH，密文可保留供恢复使用。若同时撤回原生诊断，使用本轮应用备份中的旧 `deploy/compose.napcat.yml` 恢复Compose，执行一次受控重建；保留现有QQ/config/plugins目录，不恢复旧config.json或会话数据。只撤回管理页时，按备份恢复bridge.js、console.html与对应harness后重载桥接即可。

应用和系统单元应在安装前备份，恢复时选择你自己此次部署生成的备份目录。验收结果、日志与凭据保存在部署机器的私有运行目录，不随公开源码提供。
