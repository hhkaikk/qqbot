# 费用保护与消息诊断

在工作台的「Token用量」顶部设置预算，在「最近活动」查看处理轨迹和服务异常。查看页面不调用模型；只有点击「保存策略」才写入保护配置。

## 预算口径

- 按北京时间00:00至下一天00:00统计已记录的计费请求，缓存命中、未命中、输出按现有价目表分别计价。未知日期历史和累计投影不摊入今天，金额不是官方余额。
- 每日总预算、会话预算可留空，表示不设金额上限；0表示不再允许自动聊天。到80%在工作台提醒，到上限暂停新的自动聊天。@、名字唤醒、私聊和管理员唤醒保留。
- 已经启动的模型回合不会被实时中断，尚未报告的用量可能未入账；这不是严格的扣费上限。后台收尾、旧社交自动回合、摘要和黑话学习同样检查自动预算，离线队列恢复时再核对。
- 默认异常保护开启：同一会话5分钟内12次自动唤醒，或80次已记录计费请求，会冷却10分钟，直接互动仍保留。冷却写盘，重启不能跳过；关闭异常保护不影响已设置的金额限制。
- 账本读取失败或该时间段可能缺少已淘汰请求时显示「费用暂不可核对」，不把较小的剩余数字当完整金额。此时设置了金额上限的自动聊天暂缓，直接互动保留。当前未设置金额上限时，仍执行可核对的自动唤醒次数保护。

## 诊断口径

记录接收、排队、实际投递、模型开始和网关发送回执的时间；只有完整的对应阶段才给耗时，缺失显示未知。新来信不覆盖正在处理的旧轮次；模型失败后的错误提示不会被算成成功回复。网关接受回复不代表对方已读，模型处理完成但未发言显示为观察完成。

异常仅存固定分类（余额不足、超时、鉴权、网络等），不保存聊天正文、模型回复或原始错误串。只从上线后开始记录；旧轮次无法可靠还原。轨迹最多200条、异常最多60条，重启期间未完成的轨迹显示中断，不伪造成功。

## 文件与接口

- `state/budget-policy.json`：管理员设置；`state/budget-runtime.json`：有界唤醒与冷却；`state/message-diagnostics.json`：有界诊断，均仅在服务器私有目录保存。
- `GET /dashboard/api/operations`：只读。`POST /dashboard/api/budget-policy`：唯一新增公网写入口，必须管理密码、JSON、正确页面Origin，智能体拒绝访问。
- 公网来源通过私有配置`dashboard.publicOrigin`明确设置，仅用于预算接口，不给其他管理路由增加Origin例外。Nginx只允许精确`/qqbot/api/budget-policy`路径POST，其余公开工作台路径仍仅GET。

回归：`node --test scripts/test-spend-guard.mjs scripts/test-message-diagnostics.mjs scripts/test-operations-ledger.mjs scripts/test-operations-bridge.mjs`。本地UI夹具明确标注演示数据，`operations-ui-check.js`仅允许4187端口合成演示，不对生产执行测试策略。
